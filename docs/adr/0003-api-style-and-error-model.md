# ADR 0003 — Стиль API та обробка помилок

**Дата:** 10.11.2026  
**Статус:** Прийнято

## Контекст

Для роботи із завданнями потрібно визначити HTTP-методи та єдиний формат відповідей.

## Рішення

Для TaskTracker використовується REST API.

Основні маршрути:

- `GET /tasks` — отримання списку.
- `POST /tasks` — створення завдання.
- `GET /tasks/{id}` — отримання за ID.
- `PATCH /tasks/{id}` — оновлення.
- `DELETE /tasks/{id}` — видалення.

Коди відповідей:

- `200` — успішний запит.
- `201` — створено запис.
- `204` — запис видалено.
- `400` — помилка валідації.
- `404` — завдання не знайдено.
- `500` — внутрішня помилка сервера.

Помилки повертаються у форматі JSON із полями `error`, `code` і `details`.

Контракт API описано у файлі `docs/api/openapi.yaml`.

## Наслідки

Клієнт отримує передбачувані відповіді, а розробнику простіше перевіряти та знаходити помилки.

Зміни API необхідно узгоджувати з OpenAPI-документацією.

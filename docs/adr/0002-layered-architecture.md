# ADR 0002 — Поділ коду на шари

**Дата:** 10.11.2026  
**Статус:** Прийнято

## Контекст

Після додавання CRUD у TaskTracker виникла потреба відокремити обробку HTTP-запитів від логіки роботи із завданнями.

## Рішення

Код розділено на три частини:

- `api/` — приймає запити та повертає відповіді.
- `service/` — перевіряє дані й виконує операції з SQLite.
- `domain/` — містить моделі предметної області, створені в попередній практичній.

Напрямок залежностей: API → Service. Доменні моделі розвиваються окремо.

API не повинен напряму виконувати SQL-запити. Перевірки та операції із завданнями розміщуються в сервісному шарі.

## Наслідки

Код простіше підтримувати й тестувати. У майбутньому можна змінювати реалізацію бази даних, не переписуючи HTTP-маршрути.

Поки що сервіс безпосередньо працює з SQLite, без окремого шару репозиторіїв.

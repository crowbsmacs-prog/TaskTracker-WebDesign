# ADR 0001 — Вибір архітектури TaskTracker

**Дата:** 10.11.2026  
**Статус:** Прийнято

## Контекст

TaskTracker — невеликий навчальний вебзастосунок для роботи із завданнями. Зараз він використовує Node.js, Express та SQLite.

Проєкт розробляється самостійно, тому немає потреби розділяти його на декілька незалежних сервісів.

## Рішення

Для TaskTracker обрано модульний моноліт.

Код буде розділено на три основні частини:

- `api/` — обробка HTTP-запитів;
- `service/` — логіка роботи із завданнями;
- `domain/` — моделі предметної області.

Усі частини працюватимуть в одному застосунку.

## Альтернатива

Розглядався варіант із мікросервісами. Але для невеликого проєкту це додало б зайвої складності в налаштуванні та підтримці.

## Наслідки

Перевагою вибраного підходу є простота запуску й тестування.

Недолік — окремі частини системи поки не можна розгортати незалежно одна від одної.

Якщо проєкт значно збільшиться або виникне потреба в незалежному розгортанні модулів, архітектуру можна буде переглянути.

# Практична робота №2 — Roadmap TaskTracker

**Період планування:** наступні 4 навчальні тижні (орієнтовно тижні 3–6).  
**Поточний стан:** виконано базову версію з `GET /items`, HTML-клієнтом та SQLite.

| Тиждень | Запланована робота | Критерій готовності |
|---|---|---|
| **3** | Покращити API списку: фільтрація, прості перевірки даних, повідомлення про помилки | `GET /items` повертає коректні відповіді; додані перевірки |
| **4** | Спроєктувати базову авторизацію й ролі Студент/Викладач | Описаний контракт і мінімальний прототип входу |
| **5** | Реалізувати CRUD завдань: створення, читання, редагування, видалення; додати статус | Основні маршрути перевірені тестами, дані зберігаються в SQLite |
| **6** | Розробити нагадування (прототип), покращити інтерфейс і тестування | Показ нагадувань та відображення помилок; оновлена документація |

## Залежності та порядок робіт

1. Спершу узгодити структуру даних і контракти API.
2. Перед додаванням операцій запису реалізувати базову валідацію.
3. Ролі та доступ потрібні перед відкриттям функцій викладача для користувачів.
4. Після кожного етапу перевіряти застосунок і фіксувати зміни через окрему гілку та Pull Request.

## Ризики та план дій

- **Обсяг функціональності:** у разі браку часу спочатку завершити CRUD, а нагадування залишити прототипом.
- **Проблеми із БД:** перед зміною схеми створювати резервну копію локальної SQLite БД.
- **Помилки після змін:** запускати перевірки API та тестувати відображення списку у браузері.

## Примітка

Це **план**, а не перелік уже виконаних функцій. Поточна версія реалізує лише завантаження списку завдань із SQLite.

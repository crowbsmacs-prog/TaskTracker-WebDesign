## 1. Назва та опис системи

**TaskTracker** — навчальний вебзастосунок для перегляду й подальшого керування завданнями. Він допомагає студентам бачити список навчальних справ в одному місці, а викладачам — організовувати завдання для виконання. Основна ідея — простий інтерфейс, зрозумілий навіть без спеціальної підготовки.

У поточній версії (практична №1) є вебсторінка з кнопкою **Load items**, сервер на **Node.js + Express** та локальна база даних **SQLite**. Після натискання кнопки браузер викликає `GET /items`; сервер читає записи з таблиці `items (id, name)` і повертає JSON-масив. На сторінці відображається список завдань.

Надалі TaskTracker планується розвинути до системи створення, редагування, виконання й відстеження завдань із базовою авторизацією, статусами та нагадуваннями. Ці можливості описано як **заплановані**, вони ще не реалізовані у першій версії.

## 2. Користувачі та ролі

| Роль | Призначення | Основні дії |
|---|---|---|
| **Студент** | Основний користувач | Переглядає завдання; у майбутньому відзначає виконані |
| **Викладач** | Організатор навчальних завдань | У майбутньому створює та оновлює завдання |
| **Адміністратор** (майбутня роль) | Підтримка системи | Керує обліковими записами та доступом |

У поточній версії авторизації та розмежування прав немає: список доступний через `GET /items`.

## 3. Основні сценарії використання

1. **Перегляд списку (реалізовано).** Користувач відкриває головну сторінку, натискає **Load items** та бачить завдання з SQLite.
2. **Створення завдання (планується).** Викладач вводить назву, опис і термін; система зберігає нове завдання.
3. **Зміна стану (планується).** Студент позначає завдання виконаним, після чого змінюється його статус.
4. **Фільтрація (планується).** Користувач переглядає активні, завершені або прострочені завдання.
5. **Нагадування (планується).** Система повідомляє користувача про наближення терміну виконання.

## 4. Функціональні вимоги

**Поточна версія:**
- FR-01. Відображати HTML-сторінку TaskTracker.
- FR-02. За натисканням **Load items** надсилати `GET /items`.
- FR-03. Читати записи із SQLite-таблиці `items`.
- FR-04. Повертати список у JSON та показувати його в браузері.
- FR-05. Показувати повідомлення при помилці завантаження.

**Наступні версії (план):**
- FR-06. Створення, оновлення та видалення завдань (CRUD).
- FR-07. Статуси: нове, у процесі, виконане.
- FR-08. Пошук і фільтрація завдань.
- FR-09. Вхід користувача та розмежування ролей.
- FR-10. Нагадування про терміни виконання.

## 5. Нефункціональні вимоги

- **Зручність:** простий адаптивний інтерфейс українською мовою, зрозумілі кнопки та повідомлення.
- **Швидкодія:** для типового локального списку відповідь API має відображатися без відчутного очікування; швидкодію слід перевіряти тестами, а не припускати.
- **Надійність:** помилки API не повинні призводити до зависання сторінки; користувач бачить повідомлення.
- **Безпека (план):** перевірка введених даних, мінімальні права доступу, без зберігання паролів відкритим текстом.
- **Підтримуваність:** розділення клієнта, HTTP-обробників та роботи з БД у наступних версіях.
- **Відтворюваність:** інструкція запуску й залежності зберігаються в репозиторії GitHub.

## 6. Обмеження системи

- Поточна версія працює локально і не розміщується на публічному сервері.
- База даних — локальний файл SQLite; багатокористувацький доступ поки не реалізований.
- На цьому етапі **немає** реєстрації, входу, ролей і нагадувань.
- Система не оброблятиме платежі та не буде повноцінною навчальною LMS-платформою.
- Немає мобільного застосунку — лише вебінтерфейс.

## 7. Бізнес-цінність та межі першої версії

TaskTracker зменшує потребу вести список навчальних завдань у різних місцях. У першій версії доведено сам принцип взаємодії **Client → Backend → SQLite**. Подальша робота буде спрямована на функціональність керування завданнями, авторизацію і контроль якості.
